Автоматизация сохраняет сценарий запуска и повторяет его по расписанию или по условию, а вы
наблюдаете за журналом вместо ручного старта каждый раз.

Описание раздела — на странице [Автоматизация задач](https://teletraff.com/ru/modules/automation).

## Что понадобится до настройки

- **Задача, которую вы уже запускали вручную** и понимаете её результат.
- **Свободные аккаунты на момент срабатывания.** Расписание не создаёт аккаунты — если в нужный час
  парк занят, запуск не состоится.

<Aside type="caution" title="Сначала руками">
Автоматизация повторяет сценарий, а не проверяет его разумность. Запуск, который не отработал
вручную, будет так же не отрабатывать по расписанию — только теперь регулярно и без вашего внимания.
</Aside>

## Что автоматизировать имеет смысл

| Сценарий | Почему подходит |
| --- | --- |
| Регулярный [прогрев](/modules/account-warmup/) резерва | подготовка не требует вашего участия |
| Периодический [сбор базы](/modules/parsers/) | аудитория обновляется без ручного запуска |
| Наблюдение за новыми постами | нужен постоянный, а не разовый режим |

Разовые кампании с ручной проверкой результата обычно автоматизировать не стоит: экономия
не окупает риск повторить ошибку многократно.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Автоматизация непроверенного сценария | ошибка повторяется регулярно и без наблюдения |
| Расписание без учёта занятости парка | запуск не состоится, аккаунты заняты |
| Слишком частое срабатывание | нагрузка на аккаунты растёт быстрее, чем результат |
| Включил и забыл | журнал существует именно для того, чтобы в него смотреть |

## Ограничения и правила платформы

Регулярность делает автоматизацию заметнее для платформы, чем разовый запуск: одинаковые действия
в одно и то же время — узнаваемый шаблон. Правила Telegram при этом действуют так же, как
и при ручном запуске. Подробнее — [«Безопасность аккаунтов и данных»](/security/).

## Частые вопросы

**Какие задачи можно поставить на расписание?**
Поддерживаемые задачи панель показывает при выборе. Список зависит от модуля.

**Что будет, если в момент запуска аккаунты заняты?**
Запуск не состоится — расписание не освобождает аккаунты. Это видно в журнале.

**Можно ли выключить сценарий, не удаляя его?**
Да, сценарий включается и выключается отдельно от своей конфигурации.

**Где смотреть, что происходило?**
В журнале запусков: каждое срабатывание записывается с результатом.
